## Build locally on Windows

Run from any working directory as Mark:

```powershell
powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File C:\Users\Mark\Documents\transmission-control\scripts\windows-release.ps1
```

This configures and builds Release with Qt 6.12 LLVM-MinGW, stages dependencies,
signs Planetary.exe and the LLVM runtime DLLs, builds and signs the Inno Setup 7
installer and embedded uninstaller, and writes its SHA-256 hash. Existing vendor signatures are preserved. It does not install
or launch the application. Exit code 0 means success; a nonzero code means failure.
Do not publish an older artifact after a failed build.

Check prerequisites and signing configuration without compiling:

```powershell
powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File C:\Users\Mark\Documents\transmission-control\scripts\windows-release.ps1 -CheckOnly
```

Options: `-Jobs 4` limits parallel compilation (default 4); `-SigningConfig
C:\absolute\path\config.json` selects an alternate local config; `-Unsigned`
explicitly permits unsigned validation output. Signed builds are the default.
Concurrent builds in the same checkout are rejected.

## Invoke from macOS/Linux over SSH

Replace WINDOWS_HOST with this Windows computer's hostname or address:

```sh
ssh -T Mark@WINDOWS_HOST 'powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File C:\Users\Mark\Documents\transmission-control\scripts\windows-release.ps1'
```

Append `-CheckOnly` inside the quoted command for an SSH preflight. SSH key login
and host-key trust must already be set up. Do not bypass host-key verification.
The direct command builds the current Windows checkout; it does not fetch, pull,
commit, or change branches. Inspect the checkout before building if a specific
revision is required. An SSH connection failure is separate from a build failure.

There is also `scripts/build-windows-remote.sh` for building a specific pushed
commit and copying results back to a Mac. See the main Windows README for its
clean-checkout requirements. Use the direct command above for the simplest handoff.

## Follow-up: SSH signing failure diagnostics

The desktop session successfully signs a scratch executable with the configured
PFX. The SSH failure is not reproduced locally, so its cause is not yet confirmed.
The earlier preflight only opened the PFX with PowerShell; that did not prove
SignTool could use the private key in an SSH logon session.

The signing helper now makes `-CheckOnly` perform an actual SignTool operation on
a temporary copy of an executable, verifies the signer, and removes the scratch
file. SignTool `/debug` output includes the counts after the EKU, expiry, and
private-key filters. It does not print the PFX password. Run the same documented
SSH command with `-CheckOnly` before another compile and retain the complete
filter output. The corrected signing preflight passed locally.

If the private-key filter drops the certificate only over SSH, investigate key
provider/profile access in that logon session; do not assume a bad password or
regenerate the certificate. If the EKU or expiry filter drops it, investigate the
certificate usage or Windows clock. Do not import the certificate into trusted
roots or weaken SSH host-key checks to resolve this signing issue. Do not publish
old artifacts after a failed signing test.
